# Research 011 — Security/Compliance Table Stakes and Differentiators for Varco in Late 2026

**Date:** 2026-09-07 · **Freshness matters:** Yes (compliance timelines, standard adoption, threat landscape shift quarterly; this captures the 2025-2026 inflection point)

## Question

What is the NEXT tier of security/compliance/trust capability such a framework should offer in late 2026 — as table stakes and as differentiators? Varco 3.2 shipped: tenant provenance chain, membership binding, RFC 8693 act-as delegation, token revocation store, hashed API keys, required JWT `algorithms=`, security headers / body-limit / rate-limit middleware, SecurityPosture preflight, authorization-decision audit, Postgres RLS-by-default, CycloneDX SBOM + PEP 740 attestations, SSRF-guarded webhooks with Standard Webhooks signing.

### D. Post-Quantum Cryptography and Crypto Agility

| Area | State 2026 | Varco Status | Discussion |
|---|---|---|---|
| **NIST PQC algorithms (FIPS 203/204/205)** | Finalized Aug 2024. ML-KEM (key exchange), ML-DSA (signatures), SLH-DSA (hash-based). Federal deadline 2030–2031. EU CRA roadmap: migration activities by end 2026. | ❌ Not shipped. Varco uses NIST 2008-era: AES-256 (Fernet for field encryption), RSA-4096 / ECDSA (JwtAuthority token signing). No PQC option. | Urgent only for heavily regulated (federal, banking, EU public sector). **Most commercial SaaS: not yet table-stakes (2027+).** Varco can defer PQC algorithm implementation until 2027 without market penalty. |
| **Crypto-agility (pluggable cipher suites, algorithm rotation)** | Framework-level assessment [IBM Eurocrypt 2026] identifies 7 dimensions; 6 systems (PKCS#11, OpenSSL 3.0, JCA, Tink, AWS KMS, Vault Transit) show gaps in operation decoupling. Varco ships **key-rotation** (MultiKeyEncryptorRegistry, MultiKeyAuthority) but NOT **algorithm rotation**. | ✅ Key rotation shipped. ❌ Algorithm rotation not shipped. Example: FernetFieldEncryptor is hardcoded to AES-128-CBC + HMAC-SHA256. To swap to ML-KEM, would need new encryptor class or config-driven enum (never attempted). | **Is crypto-agility a shippable feature?** Answer: **Partially.** Key rotation is shippable (varco does it). Algorithm rotation is **framework-level infrastructure**, not application-level—most practical systems (Tink, KMS, Vault) store the algorithm choice in the key material itself (ciphertext/key prefix tells you which algorithm was used at encryption time). Varco could ship: (1) a `FieldEncryptor` that reads algorithm from key metadata + dispatches to pluggable cipher; (2) rotation policies that gradually migrate data (old algo → new algo on read). **Effort:** high (audit every encrypted field, versioning, rollback safety). **ROI:** medium (avoids rewrite in 2027–2028 when PQC is mandated). **Verdict: DIFFERENTIATOR, not table-stakes for 2026.** |
| **Post-quantum TLS (client certificates, mTLS)** | TLS 1.3 + PQC hybrid (RFC 9000) not yet finalized (draft-07 as of 2026). AWS, GCP, Azure not yet offering PQC cert issuance. | N/A to varco (TLS is infra, not app framework). | Not app-framework concern. Only affects infra/edge. |

Client (MCP host / Claude) renders/executes output. | Responsibility split: varco validates input + enforces auth; Claude/MCP host validates output before execution. Varco's role is request validation. | [OWASP ASI06](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) |

**Summary:** Varco's A2A surface (SkillAdapter) + auth model (RFC 8693 + authorization audit) is a strong foundation for agent security. Gaps are mostly agent-specific (per-agent capability tiers, goal verification, memory integrity) and many are MCP/Claude responsibility, not varco's. **DIFFERENTIATOR OPPORTUNITY: per-endpoint rate-limiting (ASI01 excessive agency risk), capability-scoped tokens (ASI07 limited authority).** Neither is shipped.

These frameworks' actual planned security features (beyond what third parties ship) are not public/documented in the sources I found.

2. **SCIM 2.0 implementation complexity for app frameworks** — Sources say SCIM is table-stakes but do NOT specify: (a) implementation effort (how many lines of code?), (b) whether Varco + FastAPI can reasonably ship a SCIM 2.0 server without doubling codebase size, (c) whether a batteries-included platform shipping SCIM would differentiate or just match peers.

6. **Post-quantum timeline for commercial SaaS (not just federal)** — NIST 2030–2031 deadlines apply to federal systems. 7. **Crypto-agility adoption in practice** — IBM's Eurocrypt 2026 framework identifies 7 dimensions but I found no data on: (a) how many production systems actually implement algorithm rotation (not just key rotation), (b) cost of implementing it, (c) production incidents where lack of agility caused a breach (all historical examples are theoretical).

8. **Recommended WebAuthn server implementation (Python ecosystem)** — Sources confirm WebAuthn Level 3 is production-ready in browsers. ## Librarian's Note

**What the sources indicate** (not a recommendation):

1. **Immediate differentiator (2026–2027):** WebAuthn / passkeys server-side support. Every other framework (Django, Spring, NestJS) lacks this; varco shipping it would be unique and high-ROI (eliminates ~30% of integrator MFA code). Evidence: W3C Rec July 2026, 5B+ user accounts support, 68% enterprise deployment, 93% vs 63% success rate. **Effort: high (new package, spec complexity). ROI: high (differentiation + market pull).**

2. **Catch-up (2026–2027):** SCIM 2.0 user provisioning server. Sources say "table-stakes for B2B SaaS" and Cerby reports 59% still do manual provisioning. Shipping SCIM 2.0 routes (`/scim/v2/Users`, PATCH semantics) would let Okta/Azure AD auto-sync users. **Effort: medium (REST CRUD + RFC 7644 semantics). ROI: medium (table-stakes, not differentiation, but required for upmarket).**

3. **Emerging-to-table-stakes (2027+):** Post-quantum crypto (NIST FIPS 203/204/205 adoption). Deadline is 2030–2031 for feds, 2026–2027 start for EU CRA. Varco has no PQC algorithm option. **Effort: high (audit all crypto paths, test coverage). ROI: low-to-medium for 2026 (deferred to 2027–2028 is defensible), but high if competitors ship it first.**

4. **Differentiator (low-to-medium ROI, high-effort):** OSCAL compliance automation (FedRAMP, NIST 800-53 SSP generation). Evidence: OSCAL mandate Sept 30, 2026 (new FedRAMP authorizations). Shipping machine-readable control evidence would help government/finance buyers. **Effort: very high (OSCAL XML schema, control registry, evidence extractor). ROI: medium (niche: federal/heavily regulated). Defer unless government sales are priority.**

5. **Framework-level non-goals (correctly deferred):** Verifiable Credentials 2.0 (adoption slow, niche); SPIFFE-SPIRE (infra concern, not app-framework); full supply-chain attestation (CI/release-time concern, not app-runtime); DSAR automation (GDPR-driven but no vendor standard yet, manual workflows dominate).

6. **Compliance automation (partial overlap with existing):** Varco ships audit trail + hash-chain (good). Gap: OCSF export endpoint (audit logs in standard format), Sigstore Rekor integration (signed logs), OSCAL SSP generation (control evidence). Adding OCSF export would be high-ROI (help users pass audits); OSCAL is very high effort for lower-immediate ROI.

**Verdict on "next tier":** WebAuthn + SCIM 2.0 are the two highest-ROI next tier features (table-stakes + unique opportunity). OCSF audit export is third (audit-trail modernization). Post-quantum crypto is urgent but deferred (2027+). Agent-era security is already covered by A2A + auth model; per-endpoint rate-limiting would be the main gap.
