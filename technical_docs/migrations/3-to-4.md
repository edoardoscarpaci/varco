# 3.x → 4.0 migration guide

The one migration guide for varco 4.0.0 (DI standardization + the security-default flip list,
Plans 045–057, assembled by Plan 058). Sections are ordered by **what you hit first** when you run
a 3.x app against 4.0 — follow it top to bottom. Every row names its plan (`plans/0NN-*.md`) — the
design of record is one click away; the *why* lives in
[the DI guide](../features/dependency-injection.md) and each feature's own page, not here.
Finish with §11: `varco diagnose --check`.

## 0. Before you start

- **Pin `providify>=2.1.1`** — every varco 4.0 package requires it: 2.1.0 brought `@Fallback`,
  `@Requires` and `@Multibound` (Plan 045); 2.1.1 fixed a false `MISSING_BINDING` for an inactive
  binding's own dependencies that the runtime `validate()` gate would otherwise refuse on (P34,
  Plan 052).
- Read the `[4.0.0]` section of `CHANGELOG.md` once: its BREAKING blocks are in this guide's
  order.
- **Back up your webhook subscriptions** before deploying: `encryptor` becomes required on the
  durable webhook repositories and rows written in plaintext are unreadable through a real
  encryptor until you run `reencrypt_legacy_plaintext()` once (§8, data layer). (Plan 056)
- Nothing deprecated in 3.x is removed in 4.0 — every 3.x window now names 5.0.0 (§9, §10).

## 1. Your bootstrap no longer runs

**Every `bootstrap()` requires a container and returns it.** All ten (`varco_core.di` is new;
`varco_kafka`, `varco_nats`, `varco_redis`, `varco_memcached`, `varco_ws`, `varco_casbin`,
`varco_sa`, `varco_beanie`, `varco_fastapi`) are `bootstrap(container: DIContainer) ->
DIContainer`; none consults the process-global container, none returns `None`. (Plan 046)

| Old | New | Plan |
|---|---|---|
| `container = varco_x.di.bootstrap()` | `container = DIContainer(); varco_x.di.bootstrap(container)` | Plan 046 |
| `container.scan("varco_core", recursive=True)` (by hand) | `varco_core.di.bootstrap(container)` (identical effect; the documented entry point) | Plan 046 |
| `varco_fastapi.di.bootstrap(container, "myapp")` / `bootstrap("myapp")` | `varco_fastapi.di.bootstrap(container); container.scan("myapp", recursive=True)` | Plan 046 |
| `varco_fastapi.di.bootstrap(container, setup_producer=True)` / `setup_event_producer(container)` | `varco_core.di.bootstrap(container)` — `BusEventProducer` is the `@Fallback` `AbstractEventProducer` (045 A10) | Plan 046 |
| `create_varco_container("varco_core", "varco_redis", "myapp")` | `c = DIContainer(); varco_core.di.bootstrap(c); varco_redis.di.bootstrap(c); c.scan("myapp", recursive=True)` | Plan 046 |
| `varco_sa.di.bootstrap(container, User, Post)` / `varco_beanie.di.bootstrap(container, User, Post)` | `bootstrap(container); bind_repositories(container, User, Post)` | Plan 046 |
| `varco_sa.di.create_tables()` | `create_tables(container)` | Plan 046 |
| `varco_redis.di.bootstrap(container, streams=True)` | `bind_settings(container, RedisEventBusSettings, instance=RedisEventBusSettings(use_streams=True)); bootstrap(container)` — or `VARCO_REDIS_USE_STREAMS=true` in the environment (unchanged). The `bind_settings` call must come **before** `bootstrap()` / `create_varco_app()`; afterwards it raises `SettingsAlreadyBoundError` | Plan 046, 048 |
| `await varco_redis.di.async_bootstrap(container, setup_cache=True)` / `(…, streams=True)` | `await async_bootstrap(container)` — always installs `RedisCacheConfiguration`; use `bootstrap()` for scan-only; streams as above | Plan 046 |
| `await varco_memcached.di.async_bootstrap(container, setup_cache=False)` | `bootstrap(container)` | Plan 046 |
| `await varco_memcached.di.async_bootstrap()` | `await async_bootstrap(container)` | Plan 046 |
| `DISessionMiddleware(app)` / `app.add_middleware(DISessionMiddleware)` | `app.add_middleware(DISessionMiddleware, container=container)` or `install_middleware_stack(app, [(DISessionMiddleware, {"container": container}), …])` | Plan 046 |
| `varco_fastapi.middleware.session.get_container()` | removed — pass the container you built | Plan 046 |
| `from varco_fastapi.di import bind_mcp_adapter, bind_skill_adapter` | still works — now true re-exports with their real signatures | Plan 046 |
| `setup_varco_defaults()` / `varco_fastapi.di.bootstrap(container, setup_defaults=…)` | delete the call and the kwarg — `VarcoFastAPIConfiguration.task_serializer` is the `@Fallback` `TaskSerializer` default; override with `container.bind(TaskSerializer, MySerializer)` in any order | Plan 045 |

- **`bind_*` and `enable_*` return the container and never silently lose a binding.** A second
  registration of the same `(interface, qualifier)` raises `varco_core.di.AlreadyBoundError`
  (previously appended, and the first registration silently won). `bind_websocket_adapter`/
  `bind_sse_adapter`/`bind_mcp_adapter`/`bind_skill_adapter` gain `qualifier=`.
  `enable_authorization_audit`'s double-wrap `RuntimeError` is now `AlreadyBoundError` (a
  `RuntimeError` subclass). In tests, replace a binding with providify's `di_overrides`, not a
  second call. (Plan 046)
- **New**: `varco_core.di.bind_instance(container, Interface, obj, *, qualifier=None,
  disposer=None)` and `is_user_bound(container, Interface, qualifier=None)`. (Plan 046, 050)
- **Removed**: the "returns `None` when providify is not installed" paths; varco never reads the
  process-global container (providify's `di_global` fixture is for *your* code's tests). (Plan 046)

## 3. Backends must be selected

**Bootstrapping a backend package no longer makes it live.** Set one variable per seam the package
serves (or bind your own implementation in code, which wins over any variable). Unset means the
in-process default (`memory`; `null` for revocation); values are exact and lower-case; an unknown
value fails `create_varco_app()` with `BackendSelectionError`. (Plan 047)

| Package you bootstrap | Add to the environment | Plan |
|---|---|---|
| `varco_kafka` | `VARCO_EVENT_BUS_BACKEND=kafka`, `VARCO_DLQ_BACKEND=kafka` | Plan 047 |
| `varco_nats` | `VARCO_EVENT_BUS_BACKEND=nats`, `VARCO_DLQ_BACKEND=nats` | Plan 047 |
| `varco_redis` | `VARCO_EVENT_BUS_BACKEND=redis` (+ `VARCO_REDIS_USE_STREAMS=true` for Streams, unchanged), `VARCO_DLQ_BACKEND=redis` or `redis-streams`, `VARCO_CACHE_BACKEND=redis` or `layered`, and — new capabilities — `VARCO_IDEMPOTENCY_BACKEND=redis`, `VARCO_JOB_STORE_BACKEND=redis`, `VARCO_REVOCATION_BACKEND=redis` | Plan 047 |
| `varco_memcached` | `VARCO_CACHE_BACKEND=memcached` | Plan 047 |
| `varco_sa` | `VARCO_DLQ_BACKEND=sa`, `VARCO_IDEMPOTENCY_BACKEND=sa`, `VARCO_JOB_STORE_BACKEND=sa` (all three are new DI bindings; the classes were hand-constructed before) | Plan 047 |
| `varco_beanie` | `VARCO_DLQ_BACKEND=beanie`, `VARCO_IDEMPOTENCY_BACKEND=beanie`, `VARCO_JOB_STORE_BACKEND=beanie` | Plan 047 |

**Framework defaults are `@Fallback`, not priority floors** (Plan 045):

- A binding of your own registered at a **negative priority** to sit between varco's tiers, or a
  copied varco decorator line including its priority: drop the priority. Any binding without
  `@Fallback` wins over every varco default regardless of order or priority.
- A copied varco line **including `@Fallback`**: your binding is now a fallback too and ties with
  varco's (`validate()` reports `AMBIGUOUS_BINDING`). Remove `@Fallback` from your own bindings.
- `container.get_all(T)` / `InjectInstances[T]` no longer include a *shadowed* varco default
  beside your own — resolve it with `get(T, qualifier="in_memory")` if you need it.
- "Provide your override **before** `install()`/`scan()`" still works; order no longer matters.
- `container.validate()` gains a `Severity.INFO` tier (`FALLBACK_SHADOWED`, `CONDITION_INACTIVE`);
  code that treated every `report.issues` entry as a problem must filter by `severity`.
- `varco_redis.revocation.RedisScanNullTokenRevocationStoreDefault` is removed; an app that scanned
  `varco_redis` **without** calling `bootstrap()` must call `bootstrap()`.
- `/health` lists varco's own probes in registration order (membership unchanged); the
  Kafka/Redis/NATS DLQ configurations no longer register a second `*EventBusSettings` provider.

## 6. Lifecycle and startup

| Old shape | New | Plan |
|---|---|---|
| `KafkaEventBus`/`NatsEventBus` started when first resolved (`@PostConstruct`) | started by the `BUS` phase (`CoreModule`) — or `await bus.start()` in a hand-wired app; `publish()` before `start()` raises `RuntimeError` | Plan 050 |
| `VarcoLifespan` rollback after a failed `start()` stopped components in **forward** order | exact reverse (bug fix) | Plan 050 |

| `ReliabilityLifecycle.shutdown()` left the `AuditConsumer` subscribed | stopped, before the relay | Plan 050 |
| `dispatcher = WebhookDispatcher(repository=repo); dispatcher.register_to(bus, dlq=dlq)` | `modules=[…, WebhookModule()]` (in-memory fallback repository) or `WebhookModule(repository=repo)`; `VARCO_WEBHOOK_BACKEND=sa\|beanie` selects a durable one, which **requires** a `FieldEncryptor` binding; the hand form still works | Plan 050 |
| `SAWebhookSubscriptionRepository(url=…, encryptor=…)` by hand | still works; DI path: `SAConfiguration.webhook_repository` (engine from `SAConfig`, encryptor injected) | Plan 050 |

| `bind_websocket_adapter`/`bind_sse_adapter` resolved the bus lazily inside the factory | declared injection — a missing `AbstractEventBus` is a `validate()` `MISSING_BINDING`, not a `LookupError` at first request | Plan 050 |
| `enable_redis_token_revocation()` leaked its client at shutdown | closed by `ashutdown()` (`bind_instance(disposer=)`) | Plan 050 |
| `OtelConfiguration` providers never flushed | `@Disposes` → `TracerProvider.shutdown()`/`MeterProvider.shutdown()` at `ashutdown()` | Plan 050 |
| `SADeadLetterQueue`: "call `ensure_table()` at startup" | `SAModule(ensure_tables=True)` does it in `INFRA`; `False` when Alembic owns the tables | Plan 050 |
| `di_wiring` subclasses with `known_warnings` naming Plan 050 | entries removed; a new disposer warning is a bug to fix in the declaring `@Configuration` | Plan 050 |

**`create_varco_app(validate=True)` now runs `container.validate()` inside the lifespan**, after
every `async_init()` and before the first `start()`. An ERROR (`MISSING_BINDING`,
`AMBIGUOUS_BINDING`, `CIRCULAR_DEPENDENCY`, `SCOPE_LEAK`, `LIVE_REQUIRED`,
`UNRESOLVED_ANNOTATION`) refuses startup with `ConfigurationError`; `strict_validation=True` also
refuses on varco WARNING findings; INFO never blocks. Fix the binding, or `validate=False`.
(Plan 052)

Every lifespan logs a wiring report at INFO (logger `varco_core.di.diagnose`);
`VARCO_DIAGNOSE_STARTUP_REPORT=false` silences the block, `VARCO_DIAGNOSE_STARTUP_REPORT_JSON=true`
emits one JSON line. The build-time "`VARCO_MIGRATE_MODE`/`VARCO_TENANCY_ISOLATION` set but
unowned" log warnings are now `settings.unowned` report findings. New posture ids from
`CoreModule` (RO-2): `auth.jwks_refresh_off` (WARN), `auth.jwks_keysets_unloaded` (INFO),
`retention.platform_wide` (WARN), `retention.dry_run_only` (INFO), `retention.short_retention`
(INFO). (Plan 052)

## 11. Verify: run `varco diagnose --check`

```bash
uv run varco diagnose --modules app.wiring:modules --static --check   # Docker-free, CI-friendly
uv run varco diagnose --modules app.wiring:modules --check            # also runs async_init()
```

`app.wiring:modules` is a module-level list (or zero-argument callable) of the `VarcoModule`s you
pass to `create_varco_app`. A clean run exits `0` and prints (1) every seam with its live binding
and `source` (`code`/`env`/`env-dotted`/`default`) — check each backend you meant to select reads
`env`, not `default` — and (2) an empty **Findings** section (no `ERROR`/`WARNING`; the
`deprecation.fired` INFO lines name any 3.x call you still have to migrate). Then start the app:
the `SecurityPosture[...]` lines it logs are §8's ids — fix or knowingly suppress each one before
production. (Plan 052)
